# StarLight Plugins

Plugin repository for [Project StarLight](https://github.com/mooner1022/StarLight). The app's plugin store reads `index.json` from this repository and downloads plugin files from this repository's [Releases](../../releases).

> The plugins currently listed here are **sample entries** used to build the store. Their `.slp` files are stub plugins that load but do nothing.

## Layout

```
repository.json            Store metadata: name, categories, featured plugins, verified authors
index.json                 Generated by CI; the only file the store list fetches
plugins/<plugin id>/
  plugin.json              Store listing written by the plugin author
  README.md                Description shown on the plugin page (Markdown)
  icon.png                 Square icon, 512x512 recommended
  screenshots/*.png        Optional, 9:16 recommended
  published.json           Written by CI: mirrored files and their checksums
scripts/                   validate.py (pull requests), publish.py (main), build_index.py
```

Plugin files are not kept in the git tree. Each published version is a GitHub Release of this repository tagged `<plugin id>-v<version>`, so cloning the repository stays small and old versions stay available even if the author removes theirs.

## Publishing a plugin or an update

You only need your own plugin directory and the scripts:

```sh
git clone --filter=blob:none --sparse https://github.com/mooner1022/starlight-plugins.git
cd starlight-plugins
git sparse-checkout set plugins/<plugin id> scripts
```

A sparse checkout includes the files at the repository root (`repository.json`, `index.json`) but no other directories, so list `scripts` to run the local check.

1. Release the `.slp` file on your own GitHub repository (recommended), or attach it to the pull request.
2. Add or edit `plugins/<plugin id>/plugin.json` with a new entry in `releases`.
3. Open a pull request. CI checks the listing and the release file; after the merge CI mirrors the file to this repository's Releases and rebuilds `index.json`.

Do not edit `published.json` or `index.json`; CI owns them.

## plugin.json

```json
{
  "id": "dev.example.plugin",
  "name": "Example",
  "summary": "One line shown in the list",
  "authors": [{ "name": "example", "url": "https://github.com/example" }],
  "category": "utility",
  "tags": ["tag"],
  "license": "MIT",
  "source": "https://github.com/example/plugin",
  "publishedAt": "2026-01-01T00:00:00Z",
  "screenshots": [{ "file": "screenshots/1.png", "caption": "Caption" }],
  "releases": [
    {
      "version": "1.1.0",
      "source": "https://github.com/example/plugin/releases/download/v1.1.0/plugin.slp",
      "releasedAt": "2026-02-01T00:00:00Z",
      "changelog": "- New feature"
    },
    {
      "version": "1.0.0",
      "upload": "releases/plugin-1.0.0.slp",
      "releasedAt": "2026-01-01T00:00:00Z",
      "changelog": "- First release"
    }
  ]
}
```

- `id` must match the directory name and the `id` in the plugin's `assets/starlight.json`.
- `category` must be one of the ids in `repository.json`.
- Each release needs `version` and exactly one of:
  - `source`: an `https` URL on `github.com` or `raw.githubusercontent.com`, usually your own release asset.
  - `upload`: a path to the `.slp` file inside your plugin directory, committed in the pull request. CI removes it from the tree after mirroring.
- `version` must equal the `version` in `assets/starlight.json`. The PluginCore API version, dependencies and native library use are read from that file; size and SHA-256 are computed by CI.
- Files are limited to 50 MB.
- A published version is never replaced. To fix a release, publish a new version. Removing an entry from `releases` hides it from the store but keeps its GitHub Release.
